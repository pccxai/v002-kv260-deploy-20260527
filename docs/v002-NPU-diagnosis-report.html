PCCX v002 NPU 진단 보고서

2026-05-27 KV260 silicon forward 미완 7a6a6179 bit

KV260 PCCX v002 NPU 위에서 Gemma 추론 토큰을 만들기 위한 진단 결과. 무엇이 작동하고, 무엇이 막혀 있는지, 정확히 어떤 RTL 패치가 필요한지 정리.

한 줄 요약

NPU frontend (ISA decoder + AXIL slave + BUSY 진입)는 살아 있다. 그러나 backend (CVO dispatcher completion → mmio_npu_stat)가 deployed bit에 미반영이라 DONE 신호가 raise되지 않아 forward pass가 완료되지 않는다. OPEN 상태 PR #86이 정확한 root cause.

정확한 원인 — 미반영 RTL 패치 3건

현재 deployed bitstream 7a6a6179가 만들어진 시점에 다음 3개 PR이 모두 OPEN. 이 패치가 들어가야 forward backend 완성.

PR제목역할
#86 OPEN feat(stat): connect engine completion to mmio_npu_stat CVO dispatcher completion pulse를 mem_dispatcher → NPU_top status aggregation으로 wire. mmio_npu_stat이 npu_controller_top / ctrl_npu_frontend로 feed 되어 AXIL_STAT_OUT이 DONE bit을 return 가능하게 만드는 핵심 patch.
파일: mem_dispatcher.sv, npu_controller_top.sv, NPU_top.sv, TB tb_npu_top_e2e_minimal.sv (+1024 lines).
→ 이 patch가 빠져있어 DONE이 raise 안 됨. 가장 우선 머지 필요.
#90 OPEN feat(npu_top): connect result packer ready/valid and STORE writeback FROM_gemm_result_packer가 ready stall 동안 packed data를 안정적으로 hold. Global_Scheduler → NPU_top → mem_dispatcher STORE uop valid path 추가. GEMM 결과 4 × 128-bit beat를 L2에 writeback 하고 STORE done pulse를 mmio_npu_stat으로 raise.
→ GEMM 결과 데이터 path. #86와 함께 묶여야 의미 있음.
#134 OPEN Candidate: pipeline L2 URAM dout SRL path (post-impl WNS recovery) mem_L2_cache_fmap Port B READ_LATENCY_B 7 → 6 + local 128-bit out register 추가. 외부 latency 7 cycle 유지. PR #79 이후 post-impl WNS recovery용.
→ timing closure 후보. 합성에서 hold/setup 안 잡히면 적용.

핵심 raw 증거

opened: /dev/uio4
pre-status: 0x0000000000000000          ← idle 상태
sending RESET_KV_CACHE: 0x0100000000000000
  t=1s  status=0x0000000000000001 BUSY=True DONE=False
  t=2s  status=0x0000000000000001 BUSY=True DONE=False
  ... (12초까지 동일) ...
  t=12s status=0x0000000000000001 BUSY=True DONE=False

uio4/event = 0                          ← interrupt count 0 (DONE pulse 한 번도 raise X)
다른 opcode 시도:
  LOAD_WEIGHT  (0x02): 같은 결과 (BUSY 영구)
  LOAD_PROMPT  (0x03): 같은 결과
  NEXT_TOKEN   (0x04): 같은 결과

→ AXIL_STAT_OUT FIFO head가 BUSY 값 하나만 가지고 있고 더 이상 push되지 않음 = backend completion pulse를 status FIFO로 wire 안 함 = PR #86 미적용 증거.
